# VS Calculator / CalculatorTS

Этот проект — серверное приложение на **Node.js + Express** с фронтендом на чистом **HTML/CSS/JS**, предназначенное для двух основных задач:

- Калькулятор очков VS по дням недели (основная страница `index.html`).
- Калькулятор оптимальной прокачки исследований (страница `research.html`).

Ниже структура проекта и описание ключевых файлов, чтобы ты мог дальше развивать код самостоятельно.

---

## Запуск проекта

- Установка зависимостей:

```bash
npm install
```

- Локальный запуск:

```bash
npm run dev
# или
node server.js
```

Необходима переменная окружения `DATABASE_URL` (PostgreSQL). Таблицы и стартовые данные создаются автоматически при запуске.

## Основная структура

### Корень проекта

- `server.js`  
  Точка входа сервера Express:
  - настраивает `cors`, `express.json`, `express-session`, статику из `public/`;
  - вызывает `initDb()` из `db.js`;
  - подключает роуты:
    - `/api/items` — работа с пунктами для VS,
    - `/api/auth` — админ‑логин (пароль),
    - `/api/users` — пользовательские аккаунты для исследований,
    - `/api/research` — данные для страницы исследований,
    - `/api/bonuses` — типы бонусов очков.

- `db.js`  
  Инициализация PostgreSQL (через `pg.Pool`) и создание/заполнение таблиц:
  - `items` — пункты VS (основная страница),
  - `users` — пользователи (логин/пароль с bcrypt),
  - `research_items` — справочник пунктов исследований,
  - `research_states` — состояние исследований конкретного пользователя,
  - `point_bonus_types` — типы бонусов очков.

  Имеются функции‑сидеры:
  - `seedItemsFromFallbackIfEmpty()` — заполняет `items` из `data/fallback.js`,
  - `seedResearchItemsIfEmpty()` — заполняет `research_items` из `data/researchItems.js`,
  - `seedBonusTypesIfEmpty()` — заполняет `point_bonus_types` из `data/bonusFallback.js`.

  Дополнительные флаги окружения:
  - `DB_RESET=true` — дропает `research_items` и `research_states` и создаёт их заново.
  - `DB_RESET_ITEMS=true` — дропает `items` и создаёт заново.

#### Основные функции `db.js`

- `initDb()` — основной вход для настройки БД:
  - по нужным флагам пересоздаёт таблицы,
  - создаёт все таблицы, если их нет,
  - выполняет простые миграции (`ALTER TABLE ... ADD COLUMN IF NOT EXISTS ...`),
  - запускает сидеры для стартовых данных.
- `seedResearchItemsIfEmpty()` — если таблица `research_items` пуста, заполняет её на основе массива `RESEARCH_ITEMS`.
- `seedItemsFromFallbackIfEmpty()` — при пустой `items` заполняет её `FALLBACK_ITEMS`.
- `seedBonusTypesIfEmpty()` — при пустой `point_bonus_types` заполняет таблицу `POINT_BONUS_TYPES` из `bonusFallback.js`.
- Экспорт: `{ pool, initDb }` для использования в других модулях.

## Папка `data/`

- `fallback.js`  
  Массив `FALLBACK_ITEMS` — исходные пункты VS:
  - `{ _id, name, price, day }`
  - используется и как резервная таблица в памяти, и для заполнения PostgreSQL (`items`).

- `researchItems.js`  
  Массив `RESEARCH_ITEMS` — все пункты исследований:
  - `{ code, name, groupName, maxLevel, powerPerLevel, timeMinutes }`;
  - `groupName` — раздел («Развитие», «Экономика», «Герои» и т.п.);
  - данные используются для заполнения таблицы `research_items`.

- `bonusFallback.js`  
  Массив `POINT_BONUS_TYPES` — типы бонусов очков:
  - `{ name, day }`, где `day` — `'Все дни'` либо конкретный день (`'Понедельник'`, ..., `'Пятница'`);
  - используется для заполнения `point_bonus_types`.

Чтобы добавить/изменить стартовые данные — редактируй эти файлы и при необходимости воспользуйся флагами `DB_RESET*`.

## Папка `routes/`

- `items.js`  
  CRUD по таблице `items`:
  - `GET /api/items?day=...` — получить пункты (из БД или `FALLBACK_ITEMS`, если БД пустая/недоступна),
  - `POST /api/items` — добавить пункт (только для админа),
  - `PUT /api/items/:id` — обновить пункт (админ),
  - `DELETE /api/items/:id` — удалить пункт (админ).

- `auth.js`  
  Примитивный админ‑логин по паролю `ADMIN_PASSWORD` (используется только для редактирования `items`).

  Функции/маршруты:
  - `POST /api/auth/login` — проверка админ‑пароля, установка `req.session.isAdmin = true`.
  - `POST /api/auth/logout` — очистка сессии админа.
  - `GET /api/auth/status` — возвращает `{ isAdmin: boolean }` для фронтенда.

- `users.js`  
  Регистрация/логин пользователей для страницы исследований:
  - `POST /api/users/register` — регистрация, создаёт `users` и ставит `req.session.userId`,
  - `POST /api/users/login` — вход по логину/паролю,
  - `POST /api/users/logout` — выход, сессия очищается,
  - `GET /api/users/me` — текущий пользователь.

- `research.js`  
  API для страницы исследований:
  - `GET /api/research/items` — список из `research_items`,
  - `GET /api/research/state` — состояние исследований текущего пользователя (`research_states`),
  - `POST /api/research/state` — сохранение уровней / блокировок / переопределённой силы и времени на уровне пользователя.

- `bonuses.js`  
  API типов бонусов очков:
  - `GET /api/bonuses` — читает `id, name, day` из `point_bonus_types`.

- `middleware/auth.js`  
  - `requireAdmin` — проверяет `req.session.isAdmin`,
  - `requireUser` — проверяет `req.session.userId`.

## Папка `public/` (фронтенд)

- `index.html`  
  Главная страница калькулятора очков VS:
  - Переключение дней недели (ПН–ПТ).
  - Панель бонусов очков:
    - селект дня (`Все дни` / ПН–ПТ),
    - список типов бонусов с вводом процента.
  - Список пунктов дня с полями ввода количества.
  - Правый блок: итог очков и разбивка.
  - Админ‑панель для добавления новых пунктов.

- `app.js`  
  Логика основной страницы:
  - загружает `items` и `point_bonus_types` через API;
  - хранит состояние в `state` (день, пункты, количества, бонусы и проценты);
  - считает итоговые очки:
    - базовые цены берутся из базы;
    - бонусы (в процентах) применяются **ко всем пунктам, кроме “покупок”** (по тексту `...покупая наборы`);
    - сумма бонусов по активным бонусам (`Все дни` или выбранный день);
  - даёт админ‑возможность править список пунктов.

  Ключевые функции:
  - `fetchItems(day)` — загрузка списка пунктов VS с сервера для конкретного дня.
  - `fetchBonuses()` — загрузка типов бонусов очков.
  - `checkAuthStatus()` — проверка статуса админа через `/api/auth/status`.
  - `checkDbStatus()` — проверка, используются ли данные из PostgreSQL или из `fallback.js`.
  - `renderItems()` — отрисовка списка пунктов с учётом текущих бонусов и режима админа.
  - `handleQtyChange(e)` — обработчик изменения количества для конкретного пункта.
  - `updateResult()` — пересчёт итоговых очков и разбивки (с учётом бонусов).
  - `renderBonuses()` — отрисовка списка бонусов очков и привязка `oninput` к процентам.
  - `getActiveBonuses()` / `getTotalBonusMultiplier()` — выбор бонусов, действующих для выбранного дня, и расчёт суммарного множителя.
  - `isPurchaseItem(item)` — определяет, относится ли пункт к покупкам (на них бонусы не действуют).
  - `init()` — стартовая точка фронтенда: фон, проверки, загрузка бонусов и пунктов.

- `research.html`  
  Страница оптимальной прокачки исследований:
  - список всех `research_items`, сгруппированных по `group_name`;
  - для каждого — текущий уровень, сила/уровень, время (д/ч/м), флаг блокировки;
  - панель ввода доступного времени;
  - кнопки:
    - «Рассчитать оптимальную прокачку» — жадный алгоритм по ratio (сила/мин) на **+1 уровень**;
    - «Сохранить мои уровни» — отправка в `research_states`;
  - блок авторизации/регистрации пользователя.

- `research.js`  
  Логика страницы исследований:
  - загружает пользователя (`/api/users/me`), элементы (`/api/research/items`) и состояние (`/api/research/state`);
  - сохраняет/подставляет пользовательские уровни, блокировки, переопределённые `powerPerLevel` и `timeMinutes`;
  - реализует расчёт плана прокачки (один шаг +1 уровень на элемент за раз).

  Ключевые функции:
  - `fetchJson(url, options)` — обёртка над `fetch` с обработкой ошибок.
  - `loadCurrentUser()` — загрузка текущего пользователя `/api/users/me` и обновление UI логина.
  - `loadResearchItems()` — загрузка всех пунктов исследований и состояния пользователя, последующий вызов `renderResearchItems()`.
  - `loadResearchStateForUser()` — загрузка `research_states` для залогиненного пользователя.
  - `renderResearchItems()` — группирует `research_items` по `group_name` и отрисовывает строки с уровнями, силой, временем и блокировкой.
  - `collectCurrentResearchConfig()` — собирает текущее состояние форм (уровни, сила, время, блок) в удобную структуру для расчёта/сохранения.
  - `calculateBestPlan()` — реализует жадный алгоритм выбора **одного уровня прокачки** на пункт по лучшему отношению сила/время.
  - `renderPlanResult(result)` — отрисовывает итоговую прибавку силы, использованное/оставшееся время и план по каждому пункту.
  - `saveResearchState()` — отправляет на бэкенд текущее состояние уровней/блокировок/переопределённых значений (с обработкой 401 от `requireUser`).
  - `resetResearchLevels()` — сбрасывает уровни и блокировки на странице.
  - `setupUserAuthModal()` / `openUserModal()` — логика модального окна входа/регистрации пользователя.
  - `initResearchPage()` — точка входа фронтенда страницы исследований.

- `style.css`  
  Общие стили для обеих страниц:
  - тёмная тема, сетка, шапка, карточки, модалки, тосты;
  - отдельные секции:
    - стили для бонусов (`.bonus-panel` и т.д.),
    - стили для страницы исследований (`.research-grid`, `.research-row`, групповые заголовки и т.п.).

## Как дальше расширять проект

- **Добавить новые пункты VS**:  
  - временно сбросить таблицу `items` с `DB_RESET_ITEMS=true`, скорректировать `data/fallback.js`, перезапустить сервер.
  - либо добавить напрямую через админ‑панель на `/` (пишет сразу в БД).

- **Добавить / изменить исследования**:  
  - редактировать `data/researchItems.js` и при необходимости пересоздать `research_items` с `DB_RESET=true`.

- **Добавить новые бонусы очков**:  
  - редактировать `data/bonusFallback.js` и пересоздать `point_bonus_types` (можно один раз удалить таблицу вручную или добавить новые строки SQL‑ом).

- **Менять алгоритмы**:
  - расчёт VS‑очков — `public/app.js`, функции `isPurchaseItem`, `getTotalBonusMultiplier`, `updateResult`;
  - расчёт исследований — `public/research.js`, функции `collectCurrentResearchConfig`, `calculateBestPlan`.

Если будешь добавлять новые страницы/API, придерживайся текущей схемы:

- backend: новый роут в `routes/`, регистрацию в `server.js`, таблицы/сидеры в `db.js`;
- frontend: новый `*.html` + `*.js` в `public/`, стили в `style.css` (по секциям).
